# Deepen

Add technical depth to your previous response. If the user points to one
part of it, deepen only that part.

1. Start with the conclusion in one sentence. If the deeper analysis
   changes or qualifies the original conclusion, say so first, and
   explain why.
2. Add the mechanism behind each key claim, the main trade-offs, and the
   relevant edge cases or failure modes.
3. Support a claim that would otherwise rest on trust with evidence or a
   worked example. Use only evidence you can check, such as code, docs,
   or output you have access to. Do not invent sources, numbers, or
   results. Mark a claim that you cannot check as unverified.
4. Do not repeat explanations that the previous response already gave.
   Refer to them instead.
5. Stop when more depth would not change what the reader understands,
   decides, or does.
6. Follow the always-on style rules, titled "Response style: technical
   plain English".
