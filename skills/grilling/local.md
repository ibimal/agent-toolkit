# Local additions to grilling

These rules come from this repo's workflow doc. They add to the upstream
instructions in SKILL.md, and they win where the two differ.

- **Say why each question matters.** After each question body, and
  before your recommended answer, add one line:
  `Why it matters: <one line>`.
- **Run glossary alongside the session.** When an answer settles what a
  project term means, run the glossary skill at once, so that the term
  lands in `GLOSSARY.md` before the next round. Do not batch terms for
  later.
- **Amend a higher level explicitly.** If an answer shows that a
  higher-level artifact is wrong, such as the product brief, an intent,
  or a spec, name the artifact and ask whether to amend it. Do not work
  around it silently.
- **Grilling needs the user.** It resolves only in a live exchange.
  Never answer your own questions. In an AFK run (a run that nobody
  watches), treat the open questions as a gate: park this work, and
  list the questions in the hand-back.
- **End with a readback.** When the frontier is empty, restate the goal,
  the problem, the constraints, and what done looks like. Flag anything
  that you are still unsure of. Then ask the user to confirm the shared
  understanding before anyone acts on it.
