# Local additions to readback

These rules come from this repo's workflow doc. They add to the upstream
instructions in SKILL.md, and they win where the two differ.

- **Four parts,** in this order: the goal, the problem, the constraints, and
  what done looks like. Use the terms in `GLOSSARY.md`.
- **Flag what is unsure.** Mark each point you are guessing at, so the user
  can correct it in one line.
- **Preference calls go to the user first.** If the readback surfaces a call
  that no experiment can settle, ask it before work starts. Number the
  questions when there is more than one.
