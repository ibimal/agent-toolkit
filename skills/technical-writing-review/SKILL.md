# Technical writing review

Review the given prose against the always-on technical-clarity rules.

1. Read the whole text first. Identify the reader and the purpose.
2. Report issues in order of impact: meaning lost or changed, then clarity,
   then concision.
3. For each issue, quote the smallest span, name the rule, and give a
   rewrite.
4. Do not change code, identifiers, commands, paths, configuration keys,
   or program output.
5. If the user asks for edits instead of a review, apply the fixes and list
   the changes briefly.

If the technical-clarity rules are not in your instructions, ask the user
for them before you review.
